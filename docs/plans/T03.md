## oracle.py
- `simulator_oracle(item) -> Prediction(item.d_query_clean, "ok")`: returns the stored clean
  MuJoCo target, never recomputes or simulates.
- `analytic_true_prediction(cube, query) -> Prediction`: physics.analytic_displacement at the
  true (m, mu); `analytic_displacement` re-exported from physics.py (no duplicate formula).
- `analytic_discrepancy(d_sim, m, mu, F, T)` (scalars or arrays) and
  `item_analytic_discrepancy(item)`: simulator minus analytic (PROTOCOL §2 table sign).

## physics_fit.py: physics_fit_predict(context, query, *, force_sep_min=3.0, ...)
1. Dedupe by measurement_id, keeping the first occurrence; a repeated ID with a different
   action or d_obs raises ValueError (corrupt data, not a copy). Copies change nothing.
2. Uses d_obs (what the estimator sees; equals d_clean at noise 0).
3. Same-force rule first: context pushes with |F - F_q| <= 1e-9 * max(1, |F_q|) (float
   storage only; no physical tolerance). Pooled h = sum d T^2 / sum T^4 over those pushes,
   predict h T_q^2; with one push use physics.same_force_displacement (exact d1 (Tq/T1)^2).
   Clipped same-force pushes are included: d = 0 at F_q implies d_q = 0 under the rule.
4. Otherwise line fit on moving pushes only, moving := d_obs > move_eps (1e-6 m, documented;
   absorbs negligible creep). A clipped push only says F <= mu m g (an inequality), so it
   carries no line information and is excluded.
5. Determined iff >= 2 moving pushes AND max(F) - min(F) >= force_sep_min (3 N, the E2
   "new-force" separation) among them. Otherwise not_determined with a reason
   (empty context / no moving pushes / one force level / forces too close).
6. OLS per PROTOCOL §8 and the T03 brief: d on columns (F^2 T^2, -F T^2), solved with
   np.linalg.lstsq; rank must be 2 (guaranteed by step 5, checked anyway; never a
   pseudoinverse fallback). Option fit_space="line" fits d/(F T^2) on (F, -1) instead
   (the control message's wording); default follows PROTOCOL. Flagged as open question.
7. Predict F_q T_q^2 max(A F_q - B, 0) (clipped closed form). Unphysical fits (A<=0 or
   B<=0) are still returned but flagged in reason.
- Helper `fit_line(context, ...) -> (A, B) | None` for tests; m, mu via params_from_line.
- No exact analytic inversion is applied to observations (OLS only).
