# T05 handoff: model and training (pilot)

## 1. What changed
- src/cs182_icl/model/{gpt2,tokens,predict}.py: minimal torch GPT-2 (12L, d256, 8 heads, 9,485,057 params), PROTOCOL §5 tokens + train-only norm, `model_predict` implemented.
- src/cs182_icl/train/{data,loop}.py: row sampler (11 distinct of 32 pushes, random order, seeded, on-device), synthetic rows, loop (AdamW, warmup 5% cap 2000, cosine, best/last ckpt, metrics.jsonl).
- scripts/train.py, scripts/bench_train.py, configs/train/pilot_template.json, tests/model/test_model.py, tests/train/test_train.py, docs/runbook/T05.md.

## 2. How to verify
`. .../workflow/env.sh; CUDA_VISIBLE_DEVICES=1 pytest tests/model tests/train -m "not slow" -q` (9 passed, ~3 s)
`CUDA_VISIBLE_DEVICES=1 pytest tests/train -k overfit -q -s` (slow, 131 s): "initial MSE 0.8639, final MSE 8.63e-04 at step 11232/16000, ratio 9.99e-04".
`CUDA_VISIBLE_DEVICES=1 python scripts/bench_train.py` -> 75.3 steps/s, 1.21 GiB, 0.22 min/1000 steps.

## 3. Deviations
- Nothing vendored from Garg et al.; written from scratch, so third_party/ is empty (no license issue).
- Overfit test needs lr 5e-4 with cosine over a 16000-step cap (threshold 1e-3 x initial unchanged); lr 1e-4/3e-4 constant plateaued near 5e-3..1e-2 x initial within 8000 steps. Test, not training, settings.
- Grad-norm clipping at 1.0 in the training loop (not in the spec).
- Normalization is computed by train code from train.npz only (key format in model/tokens.py) and saved to runs/<id>/meta.json; it does not read T04's meta.json `normalization` (T04 key format unspecified). Should be equal in value; compare at integration.
- Noise > 0 not implemented (pilot noise 0); d_obs fed as input, d_clean as target. `gpu_s` = CUDA-event time of training windows.

## 4. Open questions
Step budget (runbook proposes 120000) is for control to confirm against DECISIONS.md. Weight decay applies to all params incl. LN/bias (plain AdamW).

## 5. Known weaknesses
Real data not yet exercised (only synthetic, labelled; train.py refuses datasets with a `synthetic` field). wandb not wired. Val loss uses val.npz `row_idx`/`row_cube` if present, else a fixed seeded fallback.
