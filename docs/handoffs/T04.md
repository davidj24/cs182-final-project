## 3. Deviations / choices
- meta.json keys pinned for consumers: `normalization.{F,T,d_obs,asinh_d_obs}.{mean,std}` (equal to model.tokens.compute_norm, tested), `npz_sha256` {"e1.npz": ...} listed BEFORE `content_sha256` (cli `_find_hashes` takes the first dict with "sha256" in its key), `source_git_sha`, `version`. npz zip bytes embed timestamps, so determinism is shown by `content_sha256` (array bytes) and `dataset_hash`.
- E4 cell D at c=2 is a separate `e4_cellD.npz` (item_id 5000+i, E2-style query F_q in [17,22]) because eval `prefix_cases` requires a 10-push context in every e4.npz row. T06 does not read it yet.
- E2: one duration multiset per (item, c) shared by cells A,B,C,D; no context duration equals k_q; durations distinct within a context; C/D forces stratified evenly (middle 80% of equal-measure strata; C excludes +-1 N around F_q for its other forces); each row has its own fresh ids; rows across c are independent draws (not nested). Query ids are not stored (queries are not measurements).
- E3 copies alternate base pushes; base order randomized once per item; rows k=0,1,2,4 nest. Test-set cubes: one per item (E1/E4 100/50, E2/E3 50 each).
- Val rows: 1000 = 10 per cube, 11 distinct pushes, random order, seed-fixed.

## 4. Open questions
Should T06 consume `e4_cellD.npz` (E4 optional cell)? Item ids 5000+ do not pair with e4.npz.

## 5. Known weaknesses
Zero timeouts/rotation flags in this idealized 1D simulator, so the flag-keeping path is only exercised by counting (no real flagged example). Noise > 0 not supported. Sample-level independence of actions from cubes holds by separate RNG streams (card shows corr ~ 0).
